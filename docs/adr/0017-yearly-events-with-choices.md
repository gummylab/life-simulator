# เหตุการณ์รายปีมีทางเลือก: เปลี่ยนปีหนึ่ง ๆ จาก "อ่าน" เป็น "ตัดสินใจ"

ก่อนรอบนี้ ลูปของเกมคือ "เลือกกิจกรรม → จบปี → อ่านว่าปีนั้นเกิดอะไร" เหตุการณ์ทั้งหมด (`EventEngine.fire`) โยนโอกาส 60% แล้ว `applyEffects` ลงบนตัวละครทันที ปิดท้ายด้วยการเขียนบรรทัดเดียวลง `timeline` ผู้เล่นจึงไม่มีอำนาจตัดสินใจในสิ่งที่ *เกิดขึ้นกับชีวิต* เลย มีแต่เลือกกิจกรรมที่กินเวลา เกมแนวเดียวกันส่วนใหญ่ผลักดันจังหวะสำคัญด้วยเหตุการณ์ที่ถามกลับ ซึ่งเป็นช่องว่างที่ใหญ่ที่สุดของเกมนี้ตอนนั้น

## กลไก

**โมเดล**: `LifeEvent` เพิ่มฟิลด์ `options?: readonly EventOption[]` โดย `EventOption` มี `text` (ป้ายปุ่ม) `effects` (ค่าสถานะ/เงิน) และ `resultText` (บรรทัดที่จะบันทึกหลังเลือก) ทางเลือกไม่มี `condition` ของตัวเอง เพื่อให้สิ่งที่ผู้เล่นเห็นคือสิ่งที่เลือกได้เสมอ และ `effects` ยังเป็นข้อมูลล้วนเพื่อให้ test สแกนหาพิมพ์ผิดได้เหมือน `condition`

**เครื่องยนต์**: `fire()` เปลี่ยนสัญญาจาก `string | null` เป็น `PendingEvent | null`
- เหตุการณ์ที่**ไม่มี**ทางเลือก: `applyEffects` แล้วคืนข้อความที่ render แล้ว (พฤติกรรมเดิมทุกประการ ลำดับการสุ่มเท่าเดิม ทำให้ save เก่าที่มี seed เดิมยังได้ผลเดิม)
- เหตุการณ์ที่**มี**ทางเลือก: ไม่ apply อะไรเลย คืนข้อความพร้อมป้ายทางเลือกที่ render แล้ว
- การแทนโทเคนทำครั้งเดียวต่อเหตุการณ์: สุ่ม `{place}` หนึ่งครั้งแล้วใช้ค่าเดียวกันทั้งประโยคคำถามและทุกทางเลือก ป้ายและผลลัพธ์จึงไม่พูดถึงคนละเมือง

**สถานะค้าง**: `GameState.pendingEvent` (optional, `SAVE_VERSION` คงเป็น 1) เก็บ `eventId` + ข้อความที่ render แล้ว + ป้าย/บรรทัดผลลัพธ์ที่ render แล้ว **ไม่เก็บ effect** เพราะ effect อ่านจาก `content` ตอนตอบ (`Game.resolveEvent` ค้นเหตุการณ์ด้วย `eventId` แล้ว apply `options[index].effects`) วิธีนี้ทำให้เนื้อหาเป็นแหล่งความจริงเดียว ขณะที่ข้อความถูกแช่แข็งแบบเดียวกับ `timeline` ดังนั้น refresh หรือโหลดไฟล์กลับมาแล้วผู้เล่นเห็นคำถามและผลลัพธ์ชุดเดิมเป๊ะ

**กติกาการรอคำตอบ**: การ์ดคำถามไม่ล็อกหน้าจอ ผู้เล่นยังใช้เวลาของปีทำกิจกรรมต่อได้ แต่**เหตุการณ์ใหม่จะไม่ถูกโยนทับ** ตราบใดที่คำถามยังค้าง ถ้าปล่อยข้ามปี ระบบจะบันทึก "ปล่อยเรื่องที่ค้างไว้ผ่านไปโดยไม่ได้ตัดสินใจ" แล้ว *ไม่* โยนเหตุการณ์ใหม่ในปีนั้น (คำถามที่ถูกเมินจึงมีราคา) ทางเลือกนี้ทำให้ไม่มีทางที่คำถามจะพะรุงพะรังหรือมี timestamp ของปีผิด

**หน้าจอ**: `YearEventView` เป็นการ์ดบนแท็บชีวิต เหนือฟีดรายปี ปุ่มส่งคำสั่ง `event:<index>` ผ่าน `data-do` ชุดเดียวกับปุ่มอื่น แล้ว `App` เรียก `Game.resolveEvent` บันทึกและ render ใหม่ ผลลัพธ์โผล่ในฟีดรายปีทันทีในฐานะบรรทัดของปีปัจจุบัน

**เนื้อหา**: 8 เหตุการณ์ได้ทางเลือก 2 ทาง เช่น เป็นหวัด (นอนพัก vs ฝืนทำงาน) โทรศัพท์พัง (ซื้อใหม่ vs ซ่อม) ทะเลาะกับคู่ครอง (คุยกัน vs ปล่อยผ่าน) ทำโอที (รับ vs ขอเลิกตรงเวลา) ทางเลือกของเหตุการณ์ที่มีทางเลือกต้องมี `effects: {}` ที่ตัวเหตุการณ์เอง เพราะเครื่องยนต์ข้าม effect ของเหตุการณ์เมื่อมีทางเลือก (มี test บังคับ)

## Considered Options

- **การ์ดค้างบนหน้าจอ (เลือก)** เทียบกับ **modal บังคับตอบ**: modal ทำให้จังหวะของเกมถูกบังคับจากระบบ และขัดความรู้สึก "บันทึกชีวิต" ที่อ่านเองได้เรื่อย ๆ
- **เก็บ rendered text (เลือก)** เทียบกับ เก็บ index ของทางเลือกแล้ว re-render ตอนตอบ: วิธีหลังต้องสุ่ม `{place}` ใหม่ตอนตอบ ซึ่งจะได้เมืองคนละแห่งกับตอนถาม และทำให้การ replay จาก seed เดิมไม่ตรง
- **ปล่อยให้คำถามค้างข้ามปีไม่จำกัด**: ถูกตัดเพราะบรรทัดผลลัพธ์จะถูกบันทึกลงปีผิด และผู้เล่นจะสะสมคำถามที่ไม่มีวันจบ
- **ให้ทางเลือกมี condition ของตัวเอง**: ถูกตัดตาม YAGNI ทางเลือกที่มีเงื่อนไขต้องมี UI อธิบายว่าทำไมบางปุ่มหาย ซึ่งยังไม่จำเป็น
- **เก็บ effect ลง save ด้วย**: ถูกตัดเพราะคัดลอกกติกาลงไฟล์บันทึก ทำให้แก้ balance ในอนาคตแล้วไฟล์เก่าให้ผลไม่ตรงกับเกม

## Consequences

- `EventEngine.fire` คืน `PendingEvent | null` ทุกที่ที่เรียกต้องรับผิดชอบสองกรณี ผู้เรียกมีเจ้าเดียวคือ `Game.rollEvent`
- `tests/EventEngine.test.ts` ต้องอ่าน `.text` แทนตัวสตริงตรง ๆ
- `Events.test.ts` เพิ่มการสแกนทางเลือก: 2 ถึง 3 ทาง, ผลลัพธ์ไม่ว่าง, ทางเลือกต้องต่างกันจริง, โทเคนในป้ายและบรรทัดผลลัพธ์ต้องเป็นโทเคนที่รู้จัก, และเหตุการณ์ที่มีทางเลือกต้องไม่มี effect ของตัวเอง
- `tests/EventChoice.test.ts` คุมวงจรทั้งหมดที่ระดับ `Game`: ยังไม่ apply ก่อนตอบ, ตอบแล้วได้ผลเฉพาะทางที่เลือก, index ผิดไม่ล้างคำถาม, ข้ามปีแล้วหมดอายุ, ไฟล์ทรงเสียถูกทิ้ง, ตัวละครตายแล้วตอบไม่ได้
- Playtest robot ต้องตอบคำถามก่อนทำอย่างอื่น ไม่งั้นมันจะเสียเหตุการณ์ทุกปีโดยไม่รู้ตัว
- ผู้อ่านอนาคตอาจสงสัยว่าทำไมคำถามไม่มี `condition` และทำไมผลลัพธ์จึงอยู่ในไฟล์บันทึก ADR นี้คือคำตอบ
