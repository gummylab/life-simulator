# จัดหน้าตามลูปเทิร์น: ข่าวท้ายปี, HUD กระชับ, เม뉴มาก่อนการงาน

เทียบกับ BitLife แล้วช่องว่างที่ใหญ่ที่สุดที่แก้ได้ด้วย UI อย่างเดียวคือ feedback ของปี เกมของเราเป็นลูป "อ่านสถานะ → เลือกทำ → จบปี → เห็นผล" แต่ UI เดิมจัดตามข้อมูลไม่ใช่ตามลูป: `advanceYear` ยิงเหตุการณ์แล้วเก็บลง `timeline` เงียบๆ ผู้เล่นเห็นแค่ toast "ปี X จบแล้ว เข้าสู่ปี Y" ต้องเปิดแท็บบันทึกเองถึงจะรู้ว่าปีนี้เกิดอะไร และ HUD ยาว 6 บล็อก (~250px) ดันการ์ดกิจกรรมการ์ดแรกอยู่ใต้ขอบจอจอมือถือ 375×667 ทุกปี

## กลไก

**ข่าวท้ายปี (Task 5.1)**: `GameState.record()` นอกจากลง timeline แล้วยังลงลิสต์ `news` ชั่วคราวด้วย `Game.advanceYear` ล้าง news ต้นรอบ (ก่อนระบบใดๆ ทำงาน) แล้วส่งคืน `YearResult.news` บรรทัดที่ระบบบันทึกไว้ระหว่างเปิดปี (เหตุการณ์สุ่ม, ค่าขนม, เลื่อนขั้น, จบการศึกษา, ถูกไล่ออก) ลง action ที่ผู้เล่นกดเองถูกล้างออกจาก news เพราะ `record` ของมันเกิดก่อน `advanceYear` ล้าง App เก็บ `lastNews` แล้วแสดงการ์ด "สิ่งที่เกิดขึ้นในปี X" หัวเมนูจนจบปีถัดไป วิธีนี้ไม่แตะ schema ของ timeline เดิมเลย

**HUD กระชับ (Task 5.2)**: ลดเหลือ 4 แถวกระชับ: ชื่อ + chip อายุ/ปี/โรงเรียน, เงิน, เวลา+พลัง, stat pills (ไอคอน+ตัวเลข) กดขยายเป็นแถบสีตามเดิม (แดง<30 เหลือง<60) บรรทัดอัตรา BTC ย้ายไปท้ายหน้าอื่นๆ ไม่ต้องอยู่บน HUD เพราะไม่ใช่ข้อมูลตัดสินใจของปี แบรนด์ "life simulator by onlygummy" คงอยู่เฉพาะจอตั้งค่าก่อนเกิด

**ลำดับ act tab + แผงการงานยุบ (Task 5.3)**: เม뉴ขึ้นก่อนเพราะใช้ทุกปี แผงการงานยุบเป็นแถวสถานะ ("ยังไม่มีงานทำ · ดูงาน") กดเพื่อขยายเป็นแผงเต็ม แผงขยายอัตโนมัติเมื่อมีงานที่ `jobBlockReason === null` (งานเปิดรับจริง) คนว่างงานจึงเห็นงานทันทีที่ถึงวัย คนทำงานประจำเห็นแค่แถวเดียวจนกว่าจะมีงานที่ดีกว่าเปิด

**disclosure การ์ด blocked (Task 5.4)**: เมนูใช้ปุ่ม "ยังทำไม่ได้ (n)" เหมือนแผงงาน แต่ซ่อนเฉพาะเหตุผลที่ไม่ใช่อายุ การ์ด "ยังไม่ถึงวัยนี้" คงโชว์ต่อเพราะเป็นสัญญา `showFrom` ที่ให้ผู้เล่นเห็นการตัดสินใจล่วงหน้า (มติ Round 18)

**badge ใหม่ (Task 5.5)**: `GameState.seenActions` เก็บ id ที่เคยถูกนำเสนอแล้ว App บันทึก visible set เดิมเข้า seen ตอนปีจบ และตอนเริ่มชีวิต/โหลด save การ์ดที่เพิ่งโผล่ปีแรกได้ badge "ใหม่" หายไปเมื่อจบปีนั้น deterministic ไม่มี heuristic เดาความสำคัญ

**onboarding ครั้งแรก (Task 5.6)**: ไม่มี save และไม่มี flag `life-simulator.onboarded` ใน localStorage → แสดงวิธีเล่นก่อนจอตั้งค่าก่อนเกิด ปุ่ม "เริ่มชีวิตแรก" ตั้ง flag แล้วเข้าเกม flag อยู่นอก save เพราะเป็นเรื่องของผู้เล่นไม่ใช่ของตระกูล ล้าง save ไม่ต้องดูวิธีเล่นซ้ำ

**Considered Options:** อีกทางเลือกของข่าวท้ายปีคือให้ UI อ่าน timeline ของปีปัจจุบันเอง (ไม่ต้องแก้ core) แต่ timeline ปน action result ที่ผู้เล่นเพิ่งกดเห็นมาแล้ว คัดแยกออกจาก UI คือ logic ที่ควรอยู่ใน core และทางเลือกของ badge คือ heuristic คำนวณ "ความสำคัญ" ของ action แต่ถูกตัดเพราะ deterministic ดีกว่าเดาผิด
**Consequences:** `YearResult` เพิ่ม field `news` ทุก caller ของ `advanceYear`/`performAction` ต้องรับมือ (มีเจ้าเดียวคือ App) `HudView` ตัด parameter `rateNote` ทิ้ง เพิ่ม `statsExpanded` และคำสั่ง `toggle-stats`/`toggle-blocked`/`toggle-career`/`welcome-done` ใน `App.handle` Playtest robot ต้องตั้ง flag onboarding ใน `beforeEach` และย้าย assertion ออฟไลน์ไปแท็บอื่นๆ เพราะ rate note ไม่อยู่บน HUD แล้ว
