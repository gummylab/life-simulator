# กระแสการสืบทอด: ตาย → หน้าบันทึกตระกูล → เกิดใหม่

Phase 3 ทำให้ชีวิตหนึ่งจบแล้วเล่นต่อได้โดยไม่เริ่มตระกูลใหม่ ทางเลือกแรกคือปล่อยให้ core คำนวณทายาทและเปลี่ยน state ทันทีที่ตัวละครตาย แต่นั่นขัดกับ UX ที่ตกลงไว้: เจ้าของเกมต้องอ่านชีวประวัติก่อน แล้วเลือกเองว่าจะสืบตระกูลเมื่อไร จึงแยกเป็นสองเฟส คือ "วางแผน" (plan) กับ "ทำ" (apply)

## กลไก

เมื่อตัวละครตาย `App.successionPlan()` เรียก `planSuccession(state, GAME_CONTENT, new SeededRng(state.rngState))` ทุกครั้งที่ render ผลลัพธ์เป็น `SuccessionPlan | null` (`null` = ไร้ทายาท):

- `FamilyTree` รับสมาชิกจาก `state.dynasty.tree` แล้วใส่ตัวละครที่ตายพร้อมลูกทุกคน (`registerCharacter`) การค้นทายาทเดิน BFS ตาม `parentId` เท่านั้น คนตายรุ่นกลางยังพาลูกหลานรุ่นลึกที่มีชีวิตมาได้ ดังนั้นตายก่อนมีลูกจึงไม่ใช่ game over ทันทีถ้าสายอื่นในตระกูลยังอยู่
- กระโดดเวลา 60 ถึง 100 ปี แล้วจำลองรุ่นกลางแบบย่อจากลูกของผู้ตายทีละชั้น (แต่งงานอายุ 22-35, ลูก 0-3 คน, อาชีพจากแคตตาล็อก, ตายอายุ 55-100) แต่ละคนสร้างบรรทัดภาษาไทยหนึ่งบรรทัดเก็บลง `dynasty.chronicle` จำลองจบในเฟส plan ไม่มีการ replay รายปี เพราะหน้าจอมารอผู้เล่น
- มรดก = เงินที่เหลือ × สุ่ม 30 ถึง 60 เปอร์เซ็นต์ × (1 + 5 เปอร์เซ็นต์ × รุ่นใหม่) โบนัสเป็นเงินสดเท่านั้น ไม่ส่งต่อค่าสถานะ (มติ Round 17: รักษาระดับความยาก)

_rng ทุกตัวมาจาก parameter และแกน seed คือ `state.rngState` ที่แช่แข็งหลังตาย ดังนั้น render ซ้ำหรือ refresh กลางหน้าสืบทอดจะได้ทายาท ปีเกิด และบรรทัดเดิมทุกครั้ง โดยไม่ต้อง persist ตัว plan เอง_

ผู้เล่นกด "เกิดใหม่" แล้ว `continueLife(plan, state, GAME_CONTENT)` สร้าง `Character` จาก record ทายาท เริ่มที่ปีกระโดด พกมรดก คง `founderFamilyName` เดิม และย้าย `generation/tree/chronicle` เข้า `GameState.dynasty` ชุดใหม่ seed ของรุ่นใหม่ derived จาก seed เดิมเพื่อให้ replay ได้

## ผลต่อ save

`GameState` รับ block `dynasty` แบบ optional (generation, tree, chronicle) และคง `SAVE_VERSION = 1` ไฟล์ที่ deploy อยู่โหลดเป็นรุ่น 1 ไม่มีบันทึกโดยปริยาย `SaveManager` กรอง shape ของ `tree`/`chronicle` ตอนโหลด ไฟล์ทรงเสียถูกแทนด้วยค่าเริ่มต้นแทนที่จะ error

**Considered Options:** อีกทางเลือกคือ persist ตัว `SuccessionPlan` ลง save ตอนตายเพื่อให้ refresh ได้หน้าเดิมแบบไม่ต้องคำนวณใหม่ แต่ถูกตัดออกเพราะ plan เป็น pure function ของ state อยู่แล้ว การเก็บมันซ้ำคือข้อมูลที่อาจ diverge จาก seed ได้ ส่วนการ replay ปีต่อปีระหว่างข้ามรุ่นถูกตัดออกเพราะหน้าสืบทอดต้องเปิดทันทีที่ผู้เล่นกดปุ่ม ไม่มีเวลาคำนวณปีละหลายสิบปีแบบนั้น
**Consequences:** หน้าจอมีสามสถานะใหม่ใน `App`: `succession` (บันทึกตระกูล + ปุ่มเกิดใหม่), `gameover` (สถิติตระกูล + เริ่มตระกูลใหม่สองแตะ), `chronicle` (อ่านย้อนหลังจากหน้าอื่นๆ) จอบนตอนตายเลือกปุ่ม สืบตระกูล หรือ ดูสถิติตระกูล แล้วแต่ `plan` เป็น null หรือไม่ ปุ่มทำลายล้างทุกปุ่ม (เริ่มใหม่, ล้างบันทึก) ใช้กลไก `armedConfirm` สองแตะภายใน 3 วินาทีอันเดียวร่วมกัน
