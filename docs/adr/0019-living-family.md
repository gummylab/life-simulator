# ครอบครัวที่มีชีวิต: ค่าความสัมพันธ์ ญาติมีอายุขัย และทายาทรุ่นลึกมีพ่อแม่

Phase 9 มาจากรอยรั่วสามจุดที่วัดได้ในโค้ด ไม่ใช่ความรู้สึก:

1. **ความสัมพันธ์เป็นสวิตช์** `RelationshipSystem` จบงานที่ `haveChild` หลังจากแต่งงานและมีลูกแล้วไม่มีอะไรให้ทำกับคนในครอบครัวอีกเลย ไม่มีค่าความสัมพันธ์ ไม่มีกิจกรรมต่อคู่ครองหรือบุตร
2. **โครงสำหรับญาติแก่และตายมีอยู่แต่ไม่มีคนใช้** `Person.deathYear` ถูกประกาศตั้งแต่ Phase 3 และ `FamilyView` render "เสียชีวิตเมื่ออายุ N ปี" ได้แล้ว แต่ไม่มีระบบไหนตั้งค่านั้นให้พ่อแม่หรือคู่ครอง พ่อแม่จึงเป็นอมตะตลอดชีวิตที่เล่น
3. **ทายาทรุ่น 2 ขึ้นไปไม่มีพ่อแม่** `continueLife` สร้างตัวละครใหม่โดยไม่เรียก `birthFamily` เพราะคิดว่าพ่อแม่ถูกบันทึกในตระกูลแล้ว ผลคือ `family.parents` ว่างเปล่าทุกครั้ง นั่นแปลว่าหน้าครอบครัวขึ้น "ไม่มีข้อมูลพ่อในบันทึก" และงานทั้งหมดของ Phase 9 จะใช้ได้กับชีวิตแรกเท่านั้น

## กลไก

**ค่าความสัมพันธ์** `Person` ได้ฟิลด์ `bond?: number` (optional เพื่อให้ไฟล์เก่าโหลดได้) ค่าตั้งต้น `BOND_DEFAULT = 60` ปรับด้วย `changeBond()` ที่ clamp 0-100 และอ่านด้วย `bondOf()` เพื่อไม่ให้ที่ไหนต้องเขียน `?? 60` เอง ตัวเลขทั้งหมดอยู่ใน `src/core/config.ts` ตามมติเดิม

**กิจกรรมครอบครัว** เพิ่ม `family-time`, `gift-partner`, `help-parents` เป็น `SpecialAction` (ไม่ขยาย `PlayerAction.effects` ให้รองรับ bond เพราะจะทำให้ `effects` มีสองความหมายและอ่านไม่ออก) เหตุผลบล็อกใหม่คือ `partner`, `alone`, `orphan` โดย `family-time` ต้องมีญาติที่ยังมีชีวิตอย่างน้อยหนึ่งคน, `gift-partner` ต้องมีคู่ครองที่ยังอยู่, `help-parents` ต้องมีพ่อหรือแม่อยู่

**ความสัมพันธ์จืดจาง** ทุกปีที่เปิดใหม่ ญาติที่ยังมีชีวิตทุกคนเสีย bond คนละ `BOND_DECAY = 3` กิจกรรมครอบครัวให้ `BOND_GAIN` มากกว่านั้น (12/18/14) ความสัมพันธ์จึงต้องดูแลต่อเนื่อง ไม่ใช่ทำครั้งเดียวจบ ส่วนญาติที่จากไปแล้ว bond ถูกแช่แข็งไว้เท่าครั้งสุดท้ายที่ยังอยู่

**ญาติมีอายุขัย** แยก `yearlyDeathChance(age)` ออกจาก `DeathSystem` ให้ทั้งผู้เล่นและญาติใช้เส้นโค้งเดียวกัน (`baseRisk` เดิม) โดยญาติไม่มีการ์ดสุขภาพจึงทอยจากความเสี่ยงดิบ วิธีนี้ทำให้ไม่ต้องมีตารางที่สองที่ค่อย ๆ เพี้ยนออกจากกัน

**การตายของคู่ครอง** เก็บ record ไว้พร้อม `deathYear` แล้วตั้ง `married = false` ผลข้างเคียงคือปุ่มหย่าและปุ่มมีลูกให้เหตุผลถูกต้องเองทันที ("ยังไม่มีคนรัก" / "ต้องแต่งงานก่อน") ซึ่งเป็นพฤติกรรมที่ต้องการโดยไม่ต้องเขียนเงื่อนไขพิเศษ

**เงื่อนไขเหตุการณ์ผูกกับ bond** `EventCondition` เพิ่ม `minBond` / `maxBond` โดยตีความกับ **คู่ครอง** และถ้าไม่มีคู่ครองที่ยังมีชีวิต เงื่อนไขทั้งสองอย่างคืน false (ไม่มีความสัมพันธ์ให้วัด) แล้วใช้กับคู่เหตุการณ์ *เซอร์ไพร์สวันครบรอบ* (ต้องสนิท ≥ 70) กับ *ทะเลาะเรื่องงานบ้าน* (ต้องห่าง ≤ 55)

**ทายาทรุ่นลึกได้พ่อแม่** `continueLife` ค้นพ่อแม่สายเลือดใน `plan.tree` ด้วย `parentId` ของทายาทแล้วใส่กลับเข้า `family.parents` ถ้าหาไม่เจอ (ไฟล์เกาที่ tree ไม่ครบ) ก็ปล่อยว่างเหมือนเดิม ไม่ throw

**ไฟล์บันทึก** `bond` ถูก normalize ตอนโหลด (clamp 0-100, เติมค่าตั้งต้นเมื่อไม่มี) ทั้งใน `family.parents` / `family.partner` / `family.children` และใน `dynasty.tree` ไฟล์ที่ bond เกินช่วงจะไม่ทำให้แถบสีล้นจอ

## Considered Options

- **`bond` บน `Person` (เลือก)** เทียบกับ แผนที่แยก (`Record<personId, number>` ใน `FamilyState`): แผนที่แยกต้อง sync สองที่ทุกครั้งที่มีคนตาย/หย่า/เกิด และหายไปเมื่อคนนั้นย้ายเข้า `dynasty.tree`
- **เป็น `special` action (เลือก)** เทียบกับ เพิ่ม `effects.bond` ใน `PlayerAction`: ทางหลังต้องระบุว่ากระทบใคร (`partner`/`children`/`parents`) ซึ่งกลายเป็นภาษาใหม่ในชั้นข้อมูล และทำให้ `effects` มีสองชนิดความหมาย
- **ใช้เส้นโค้งความตายเดิม (เลือก)** เทียบกับ ตารางความเสี่ยงเฉพาะญาติ: ตารางที่สองจะเพี้ยนจากกันทุกครั้งที่ปรับ balance
- **แช่แข็ง bond ของคนที่ตายแล้ว (เลือก)** เทียบกับ ให้ bond ลดต่อหลังตาย: การลดต่อไม่มีความหมายเพราะไม่มีใครดูแลได้ และจะทำให้หน้าตระกูลอ่านสับสน
- **ทอยความตายของญาติ "หลัง" การทอยของผู้เล่น (เลือก)**: ทำให้ลำดับการสุ่มที่ตัดสินชีวิตผู้เล่นในปีนั้นเหมือนเดิมทุกประการ การเพิ่มญาติจึงไม่เปลี่ยนเส้นทางของปีที่กำลังเล่นอยู่
- **ยอมรับว่าทายาทรุ่น 2 ไม่มีพ่อแม่ต่อไป**: ถูกตัดเพราะมันทำให้ทั้งหน้าครอบครัวและ Phase นี้ใช้ได้แค่รุ่นแรก

## Consequences

- **การสุ่มไม่เทียบเท่ารุ่นก่อน**: การทอยของญาติต่อท้ายปีทำให้ `rngState` ที่ยกไปปีถัดไปต่างจากเดิม ชีวิตที่เริ่มด้วย seed เดิมจึงเดินคนละทางกับเวอร์ชันก่อนหน้า (ภายในเวอร์ชันนี้ยัง deterministic ทุกครั้ง) ไฟล์บันทึกยังเก็บ `rngState` จึงเล่นต่อได้ตรงเส้นเสมอ และ Playtest ยังตรึงนาฬิกาไว้
- **`rel-partner-gift` ย้ายจาก `minHappiness` ไป `minBond`** (ADR 0018 ระบุว่าเพิ่ม `minHappiness` สองที่ ตอนนี้เหลือที่ `career-newskill` ที่เดียว) เพราะความสนิทของคู่ครองเป็นเงื่อนไขที่ตรงกับเรื่องนี้กว่า
- **`rel-partner-argue` ต้องมี `effects: {}`** เพราะเครื่องยนต์ข้ามผลของเหตุการณ์เมื่อมีทางเลือก (มติ ADR 0017) ความเสียหายของการทะเลาะจึงย้ายเข้าไปอยู่ในทางเลือกทั้งสอง
- **`EventEngine.test`** ต้องเลือกเหตุการณ์ที่ gate ด้วย `married` ล้วน ๆ ไม่ใช่ตัวแรกที่เจอ เพราะตัวแรกในคลังผูกกับ bond แล้ว
- **หน้าครอบครัว** มีแถบความสัมพันธ์ต่อคนและบอกจำนวนคนที่ยังอยู่ พร้อมชี้ว่ากิจกรรมครอบครัวอยู่ในหน้าเมนู (ไม่ทำปุ่มฟรีในหน้านี้ ตามมติว่าไม่มีอะไรได้มาฟรี)
- **`ActionBlockReason`** เพิ่ม `alone` และ `orphan` ทุก `Record<ActionBlockReason, string>` ต้องมีป้ายใหม่ (มีที่เดียวคือ `MenuView`)
