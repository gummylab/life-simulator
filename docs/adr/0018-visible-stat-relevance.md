# ทำให้ค่าสถานะทั้งสี่มีผลกับกติกา: รูปลักษณ์ ความสุข และค่าขนมในเกม

`EventEngine` รองรับเงื่อนไข `minHappiness` และ `minMoney` มาตั้งแต่ Phase 2 แต่ผมนับในเนื้อหาจริงแล้วพบว่า**ไม่มีเหตุการณ์ไหนใช้ทั้งสองเงื่อนไขเลย** (`minAge` 27, `employed` 9, `student` 9, `minSmarts` 4, `married` 3, `minHealth` 2, `minHappiness` 0, `minMoney` 0) และ **`looks` ปรากฏที่เดียวในโปรเจกต์คือ `AgingSystem` ที่ลดลงปีละ 1 คะแนนหลังอายุ 35** ไม่มีงาน เหตุการณ์ หรือกิจกรรมใดอ้างถึงเลย

ผลคือค่าสถานะสองในสี่เป็นตัวเลขประดับ ผู้เล่นไม่มีเหตุผลจะสนใจรูปลักษณ์ และไม่รู้ด้วยซ้ำว่ามันมีอยู่ทำไม ซึ่งทำให้คำสัญญาของ ADR 0016 ที่ว่า "การ์ดบอกผลกระทบก่อนกด" ยังไม่พอ เพราะผู้เล่นเห็น `+6 รูปลักษณ์` แต่ไม่รู้ว่าเอาไปทำอะไร

## กลไก

**รูปลักษณ์คุมการเดท**: `LOOKS_FOR_DATING = 45` ใน `src/core/config.ts` และ `Game.specialBlockReason("date")` คืนเหตุผลใหม่ `looks` เมื่อ `looks < 45` (ตรวจ `taken` ก่อน เพราะการมีคู่รักเป็นเหตุผลที่ตรงกว่า) `MenuView` เพิ่มป้าย "รูปลักษณ์ยังไม่พอ" ให้ผู้เล่นรู้ทันทีว่าต้องปั้นค่าอะไร

**มีทางปั้นรูปลักษณ์**: กิจกรรมใหม่ `makeover` ("ดูแลตัวเองที่ร้านเสริมสวย", อายุ 12 ขึ้นไป, 25 เวลา, เสีย 0.0006 BTC, +6 รูปลักษณ์ +3 ความสุข, คืนพลัง 20) อยู่หมู่ "ดูแลตัวเอง" ทำให้รูปลักษณ์เป็นค่าที่ *เพิ่มได้* ด้วยการเลือก ไม่ใช่แค่ค่าที่เสื่อมตามเวลา (และเป็นกิจกรรมพักผ่อนที่เสียเงินตามมติเดิม) ค่าเริ่มต้นของผู้เล่นคือ 50 และการเสื่อมเริ่มที่ 35 ดังนั้นวัยหนุ่มสาวเดทได้ตามปกติ แต่คนที่ปล่อยตัวจะถูกกันจริง

**รูปลักษณ์มีผลกับงาน**: `sales` ("พนักงานขาย") เพิ่ม `statRequirement: { stat: "looks", min: 45 }` โดยใช้สนามที่มีอยู่แล้วของ `JobSpec` ไม่ต้องแก้โค้ดระบบอาชีพเลย และ `jobReasonLabel` พิมพ์ "รูปลักษณ์ไม่พอ (45)" ให้เอง

**ความสุขมีบทบาทในเงื่อนไข**: เพิ่ม `minHappiness` ให้สองเหตุการณ์เชิงบวก (`rel-partner-gift` ≥ 40, `career-newskill` ≥ 45) ตามหลักว่าคนที่มีความสุขพอจะรับรู้เรื่องดี ๆ ได้ เงื่อนไขนี้มีโค้ดรองรับอยู่แล้ว การเพิ่มจึงเป็นงานเนื้อหา ไม่ใช่กติกาใหม่

## Considered Options

- **แก้กติกาก่อน 2-3 จุดตามด้วยเนื้อหา (เลือก)**: กติกาทำให้ผู้เล่น *เห็น* ว่าค่านั้นสำคัญผ่านปุ่มที่ถูกบล็อกพร้อมเหตุผล ส่วนเนื้อหาเพิ่มความหลากหลายแต่มองไม่เห็นความเชื่อมโยง
- **เพิ่มเนื้อหาที่อ้าง `minHappiness`/`minMoney` ก่อน**: ราคาถูกกว่า แต่ผู้เล่นจะไม่ทันสังเกตว่ามีระบบนี้อยู่ และไม่ตอบว่า "รูปลักษณ์ใช้ทำอะไร"
- **ให้รูปลักษณ์คุมงานทุกงาน**: ถูกตัดเพราะเกินจริงและทำให้ผู้เล่นที่รูปลักษณ์ต่ำตันการงานไปเลย
- **ให้ `wearOff`/ริ้วรอยมีทางรักษาแบบแพงมาก**: ถูกตัดตาม YAGNI กิจกรรมเดียวที่ได้ +6 ต่อปีก็พอถ่วงเวลาการเสื่อมแล้ว
- **เพิ่ม `minMoney` ในเนื้อหา**: ยังไม่ทำ เก็บไว้ให้ Phase เศรษฐกิจ (ที่เงินจะมีที่ใช้จริง) ตัดสินใจพร้อมกัน

## Consequences

- `ActionBlockReason` เพิ่มค่า `looks` ทุก `Record<ActionBlockReason, string>` ต้องมีป้ายใหม่ (มีที่เดียวคือ `MenuView`)
- `Playtest` ยังเดทได้ตามปกติเพราะผู้เล่นวัย 20-30 มีรูปลักษณ์ราว 50 แต่ถ้ามีการปรับ `LOOKS_FOR_DATING` สูงกว่านี้ robot จะติดกับดักทันที ควรมี test ที่คุมว่าค่าเริ่มต้นผ่านเกต
- กิจกรรมใหม่ต้องมีไอคอน (`Scissors`) และถูกจัดเข้าหมู่ (`makeover → selfcare`) ไม่งั้น `Icons.test`/`ActionGroups.test` จะฟ้อง
- `TimeEnergy.test` นับกิจกรรมที่มี `energyRestore` เป็น "กิจกรรมพักผ่อน" และบังคับว่าเวลาที่น้อยที่สุดต้องไม่เกินงบวัย 3 ขวบ (60) — `makeover` กิน 25 จึงผ่านข้อนี้ แต่ทุกกิจกรรมพักผ่อนใหม่ต้องผ่านเกณฑ์เดียวกัน
- `minHappiness` ที่เพิ่มเป็นงานเนื้อหา ไม่กระทบ save และไม่ต้อง bump `SAVE_VERSION`
